### Arch

Aggregator, not a GP portal: documented Client API (OpenAPI, JWT client credentials) exposing holdings, cash flows, activities and tax documents to the investor organisation or its delegate, plus SFTP/flat-file delivery; requires paid Arch subscription and docs are not readable anonymously.

Notes: Classification: Arch is an AGGREGATOR / digital admin layer, not a GP-issued LP portal. It pulls 'statements, capital calls, and K-1s from portals and inboxes' on behalf of its clients (700+ customers, 50,000+ funds) and exposes the normalized data via its Client API and integrations (Addepar etc.). Confidence: high on API existence and resource list (API Evangelist index of OpenAPI files, 2026-07; vendor docs URL confirmed live but JS-rendered). Medium on SFTP/flat-file delivery (older vendor copy). Investor-side API: yes for the client organisation (investor or their delegate), gated by a paid subscription; auth is client-credentials JWT.

### Papermark

Owner side is the best in class: public REST API with OpenAPI, scoped tokens, CLI and a vendor MCP server from a EUR 59 plan. Not a 1 because nothing is offered to the invited LP, who still reaches documents through browser links.

Notes: Open source data room (AGPLv3, github.com/mfts/papermark, about 9.3k stars) with a hosted SaaS and self-hosting on the Enterprise plan. Next.js, Postgres, S3. SOC 2 Type II, ISO 27001, GDPR, EU hosting per vendor. Used by GPs for fundraising data rooms and investor document sharing. The most programmable data room in the registry for the owner side: public REST API, OpenAPI spec, CLI and a vendor MCP server. Recipient-side programmatic access is not offered, so an LP still opens links in the browser. Because it is open source, it is a natural first implementation target for an OIPP endpoint. High confidence (vendor docs and GitHub, 2026-11-07).
